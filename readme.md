## 娱乐功能

### 今日人设

使用 `今日人设` 或 `人设` 查看。相同用户在同一天会得到固定的称号、签运、幸运色、幸运食物、幸运方位与宜忌，第二天自动刷新。

### 猜拳

使用 `猜拳 石头 100` 和贝拉猜拳，最后的积分参数可省略。获胜得到与押注相同的积分，失败扣除押注，平局不改变积分。

* 贝拉的出拳使用 `crypto.randomInt()` 在石头、剪刀、布中随机选择
* 如果本局平局，该用户的下一局会排除相同出拳，确保不会连续平局
* `猜拳单次押注积分上限` 默认为 1000；设置为 0 时仍可进行无押注猜拳

### 积分骰子

支持 `骰子 NdM` 格式，其中 N 是骰子数量，M 是每颗骰子的面数。直接输入数字会投掷一颗对应面数的骰子，例如 `骰子 20` 等同于 `骰子 1d20`。

| 示例 | 实际骰子 | 本局费用 |
| --- | ---: | ---: |
| `骰子` | 1d6 | 9 积分 |
| `骰子 2d6` | 2d6 | 12 积分 |
| `骰子 20` | 1d20 | 23 积分 |
| `骰子 10d970` | 10d970 | 1000 积分 |

限制与结算规则：

* 骰子数量为 1～10，面数为 3～997
* 费用公式为 `3 × 骰子数量 + 骰子面数`
* 单局费用不得超过 1000 积分，积分不足时不会进行投掷
* 最低、中间、最高三个点数组合权重区间分别判定为失败、平局、胜利
* 失败扣除本局费用，平局返还全部费用，胜利返还本金并额外获得利润
* 单局最高净赚 4000 积分，数据库积分与 Monetary 使用相同的净变化值

#### 骰子权重算法

骰子的输赢不再通过额外的概率抽签决定，最终展示的骰点组合会唯一决定结果：

1. 先按照骰子总点数排序，总点数越高，组合权重一定越高。
2. 总点数相同时，再按照每轮骰点排序，让每一种骰点组合都拥有唯一排名。
3. 将全部有效组合平均分为三个连续区间，依次对应失败、平局、胜利，因此三种结果各占 1/3。
4. 如果组合总数不能被 3 整除，只将末尾最多两个边界组合自动重投，再对剩余组合严格三等分。重投不会扣除额外积分。
5. 胜利后，根据当前组合在胜利区间内的排名计算利润；越接近最高权重，利润越高。

胜利利润使用经过归一化的离散三次权重。设胜利区共有 `W` 个组合，当前组合在胜利区中的排名为 `P`（从 1 开始），利润倍率为：

```text
倍率 = W × P³ ÷ (1³ + 2³ + ... + W³)
利润 = min(4000, floor(本局费用 × 倍率))
```

归一化后，胜利区所有组合的平均利润倍率为 1。由于失败和胜利各占 1/3，长期平均积分产出与消耗基本平衡；高权重组合仍然可以获得明显更高的利润。

#### 实现优化

* 使用组合数学直接计算“点数和不超过目标值”的组合数量，不会枚举最多 `997¹⁰` 种骰点组合
* 所有组合数量和排名均使用 `BigInt`，避免大面数、多骰子时发生整数溢出
* 边界拒绝采样最多排除两个组合，对常用的多骰子表达式几乎没有额外开销
* 仅计算当前骰点组合所需的排名，10d970 的权重计算通常只需要数毫秒
* 积分按净变化结算：失败只扣款、胜利只增加净利润、平局不写数据库，减少数据库与 Monetary 调用
* 在随机与结算前先检查格式、数量、面数、费用上限和用户余额，避免无效指令改变积分

## 积分迁移至通用货币
1. 将本插件更新至2.1.0及以上版本
2. 安装 monetary 插件并启用,使用权限等级大于等于3的管理员对着bot使用命令" bella-tranferData "即可完成迁移  
3. 迁移命令仅需运行一次即可，本插件币种为"Bella"

# CHANGELOG
## 2.2.1
### 变更

* 移除通过独立概率抽签决定骰子输赢的旧逻辑，改为由最终骰点组合排名直接决定结果
* 骰子限制为 1～10 颗、3～997 面，并限制单局费用不超过 1000 积分
* 输、平、赢三个有效组合区间严格各占 1/3，无法三等分时最多重投两个边界组合
* 胜局改为返还本金并计算净利润，单局最高净赚 4000 积分

### 优化

* 使用组合计数计算骰点排名，避免枚举全部可能组合
* 使用 `BigInt` 保存组合数量与排名，避免大数精度丢失
* 使用归一化离散三次权重计算胜局利润，兼顾高点数奖励与长期积分平衡
* 数据库与 Monetary 改为按净变化同步，平局不再产生无意义的扣除与返还操作
